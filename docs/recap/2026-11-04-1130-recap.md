## Last re-run on this machine

A full reset and fresh run is the right test. It is the only way the LEAN trim
applies: undo/replan/apply would reuse the old 17.9 GB `inputs`. It also gives
a clean baseline for measuring space. The full reset replaces all of Working
(about 42 GB: run state 23, backup 5.6, `_processing` 3.7) with the 5.1 GB
Production copy, keeping only the old run's receipts in the reset review bundle.
Nothing from `fresh-20261103-core` needs retiring separately; you approved
removing it on Nov 4.

One launcher runs the whole sequence ([help](../../bin/help.cmd), 12:30):

```text
bin\rebase-flow.cmd --root "B:\Sovereign Territories Sandbox\Working" --run fresh-20261104-lean           (preview)
bin\rebase-flow.cmd --root "B:\Sovereign Territories Sandbox\Working" --run fresh-20261104-lean --apply   (run/resume)
bin\rebase-flow.cmd --root "B:\Sovereign Territories Sandbox\Working" --run fresh-20261104-lean --check   (status)
```

The default steps are full reset, originals and `--check`, a backup of the
fresh baseline, intake (`--workers 4`), matching plan, install
(`--preserve-legacy-derivatives`), install check and gallery check. All
rebase steps use `--baseline working --cast-seeds core
--record-core-protection`. The older manual list omitted the backup's
`--apply`.

Skipped by default (12:30; `--with-previews` runs them):
- the reset preview, because the reset apply recomputes the same analysis
  and refuses on any blocker;
- the intake dry-run, which is only an inventory;
- the separate intake check, because the matching plan and the install verify
  the same preparation evidence again.

Not skippable:
- The matching "preview" *is* the matching. The install only installs a saved
  plan.
- The backup copies the fresh Production state after the reset, not the old
  run, which the reset discards together with its old backup. The install
  refuses to start without a complete backup of Working, so the backup stays
  (13 min, about 6 GB; shown separately in the space table).

While it runs, the console shows a start/finish line per step with the Nov 3
time beside it, every `Plan:`/`Install:`/`Apply:` phase timing, warnings, and
a heartbeat every 2 minutes: photos done, rate, ETA, time since the last
output, and the estimated time left for the whole flow. Silence for more than
10 minutes is flagged, because it may mean a suspended process. The live
process-flow recap `tmp\session-logs\rebase-flow\fresh-20261104-lean\flow.md`
holds the step table, phase timings and space after each step. It sits beside
one log per step. A failed step stops the flow; the same `--apply` resumes
at it. Close any open `_reports\library` page, sandbox folder window or
terminal in Working before starting, because the reset refuses locked files
before it stages anything. Never prune active photo
folders.
