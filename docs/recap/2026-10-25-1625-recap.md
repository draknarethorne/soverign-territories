## The day in a few lines

The pipeline is now more than separate crop/erase demonstrations. Published
work wires prepared sandbox inputs into the shared matcher and recoverable
publication, with retained originals/variants and stable decision continuity.
The gallery can explain an exact retained photo without confusing it with
unaccepted historical experiments.

The local Python runtime was already modern. The useful change was declaring
dependencies and extending repeatable CI, not claiming an upgrade or speedup.
The final pass reconciled the art documentation so old recipes, design proposals
and unrun acceptance work no longer read as current command authority.

## What was delivered

### Prepared clean-start and retained gallery detail

- One existing launcher supports inventory, intake-only stop/check, verified
  resume into fresh-cache matching preview, reviewed install, repeat validation
  and exact undo. Legacy matcher-only previews cannot install.
- Every cast image gets preparation while cast membership remains retained.
  Loose/named Various reuse the shared planner/seeding helper. Artists receive
  scoped preparation evidence, never general identity matching.
- Selected prepared bytes feed measurement and native publication. Exact source
  bytes and kept variants/masks/detail follow supported individual photo moves
  through owner-local `gallery_org`/`gallery_intake`.
- Retained detail exposes checked current native/maintained derivatives and
  gallery/Review/run return navigation. Old experiments remain separately labelled.
- One-to-one stable-ID continuity preserves names, family, protection overrides
  and rejected-person decisions. Missing/unknown/stale/ambiguous/concurrent
  inputs refuse before reset; they are not silently discarded.
- Existing owned cast outputs and prior categories are replaced reversibly.
  Unknown/edited outputs and later user additions block destructive undo.

### Identity metadata and gallery work

- Draft independent-evidence automatic protection, persistent manual opt-outs
  and conservative organizational-family metadata share the existing backed-up
  reconciliation transaction and undo.
- Original/current/character names remain separate. Family naming does not
  rename fixed cast folders or workflow keys, and is not a biological claim.
- Shared theme/navigation/footer, responsive Reference/Identity/Actions panels,
  Review-count links and searchable run/photo history are implemented.
- Protected-action unlock, every whole-person action and gallery-driven
  execution are not claimed complete.

### Python requirements, not a machine-wide upgrade

The launchers already use regular 64-bit **CPython 3.14.3**. Pinned direct core
and CPU-intake requirements now document the tested stack; Windows CI is
configured for **3.12/3.13/3.14**, retaining the 3.12 source baseline.
The [runtime guide](../art/original-photos.md#python-runtime-and-dependencies)
owns setup and evidence. ComfyUI/CUDA, the machine interpreter and the existing
project environment were not replaced. No performance gain is claimed.

## What was good

- Tests exercised the actual launchers, existing maintained outputs and a
  second prepared rebuild, rather than just an isolated happy path.
- Browser checks caught a circular return link and misleading pilot labels
  that file-existence tests would miss.
- Retention, identity protection, core evidence, workflow choice and family
  presentation stayed distinct instead of becoming one unexplained score.
- Full-document reading exposed contradictions hidden by appended continuations.
  Keeping independent proposals/evidence avoided a cosmetic purge of useful context.

## What was bad

- Earlier summaries blurred "rendered", "selected", "implemented" and "accepted".
  Some old recipe and integration claims survived below newer delivery notes.
- The older crop order could discard eraser output; face-derived composition
  cut limbs. The user had to identify problems that systematic visual review
  should have found first.
- Long retained paths, reused names after rejection and replacing existing cast
  outputs exposed bugs only when the complete workflow was exercised.
- Large historical report verification has real I/O cost; search/pagination do
  not make regeneration free. A literal link substring test also gave a false
  negative where normal relative-link resolution was required.

## Recurring themes

body context and originals; make stages composable without multiplying flows.

as seriously as the initial transformation.

## Complexity and debt

but legacy `originals`/crop/sort paths and large report modules still create
overlapping assumptions. Remove or forward obsolete surfaces only after their
callers and recovery contracts migrate. Documentation needed the same treatment:
one current authority, bounded history and preserved rationale, not an ever-growing
stack of contradictory continuation paragraphs.
