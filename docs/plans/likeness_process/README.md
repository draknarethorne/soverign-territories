## Updating progress without drift

- Each phase records delivered reuse, missing implementation, inputs,
  steps, tests, exit evidence and gates. A new report alone cannot advance
  an implementation phase to complete.
- Checkboxes remain in the spine or existing domain owner. These sheets
  contain no duplicate execution tasks; the nested files are not another
  queue for the todo generator.
- For each implemented slice update its phase evidence row, parent summary
  and owning spine task together: input/run IDs, code, tests, runtime/human
  evidence, residuals and next gate. Do not repeat all historical results
  at the top of every document.
- Keep one primary build outcome. Extra research must identify which
  decision it will change, reuse evidence and stop at that decision.
- User reviews should resolve meaningful ambiguity or judge a changed
  outcome, not repeatedly certify the same known split.
- Keep raw feedback and historical receipts immutable. No broad document,
  source-folder or experimental-output cleanup accompanies this breakdown.
