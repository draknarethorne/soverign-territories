## Outcome

Make comparisons reproducible and honest: distinguish reference repair,
member recovery, split consolidation, appearance association, reference
contamination, unresolved cases and physical changes. A proposal count,
centroid score or unchanged installed folder is not an accuracy result.

## Work sequence

1. Freeze experiment inputs: complete saved population and applicable manual
   intent, exact selected pixels/vectors, policy/recipe, reference origin,
   code and current-versus-original lineage. Keep installed preview11 as a
   comparison, not the desired answer.
2. Maintain an effective direct-evidence ledger without rewriting raw
   exports. Record conflict resolution and revised observations separately.
   Query-level Both is not a universal label for either folder.
3. Allocate development and reserved evaluation by connected identity/
   appearance/series evidence, excluding equal-content copies and repeated
   pairs across splits. Unknown relatedness remains a leakage limit.
   Previously reviewed/tuned cases cannot be retrospectively called blind.
4. Include cast and non-cast, different poses/sessions, same-session distinct
   views, mixed old folders, lookalikes, source splits, missing measurements,
   small/reference-needed groups, explicit protection and selected-photo
   conflicts. Preserve the Vale/outlier cohort and global competitors.
5. Compare same-input variants: frozen control; member/reformation variant;
   reference-construction variant; combined variant. Add secondary cues
   separately per [03](03_secondary_evidence.md), not as an unmeasured cure.
6. Count same-person consolidation separately from corrected wrong ownership.
   Report positive-member recovery, wrong admissions, abstention/unknown,
   reference entry/withdrawal, residual contamination, supported appearance
   grouping, false split and churn, with explicit denominators and limits.
7. Measure evidence loading, comparisons, extraction, decision passes and
   publication separately. Record cache hits/invalidations, reads/bytes,
   memory and cold/warm/no-op conditions without repeating intake.

## Tests and exit evidence

Require source/packet/result binding, direct conflict/uncertainty handling,
conservation and no-self/equal-content safeguards. Test order invariance,
duplicate-session support, holdout leakage and deliberate incomplete scope.
Keep stage arithmetic parity separate from full stage replay parity.

Exit evidence is a versioned evaluation allocation and accepted numerical
budget, paired run/recipe IDs, measured outcomes and explicit no-gain/
regression disposition. Zero observed errors on a small development sample
does not establish zero general contamination risk.
